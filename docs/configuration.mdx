---
title: Configuration
description: Full field reference for config.json.
---

Each service that needs configuration defines an `Options` class, and `config.json` has one
top-level key per class, named after the class itself (e.g. `RoleSyncerOptions`). This happens
through `ConfigureTypeSection<T>`, which binds `config.GetSection(typeof(T).Name)` to `T` — so
adding a new configurable service means adding a matching section with the same name as its
`Options` class, no extra wiring required.

<Callout type="info" title="Where it lives">
    `config.json` sits alongside `secrets.txt` in the bot's working directory (see
    [Getting Started](./getting-started.mdx)) — it isn't checked into the repo since values like
    Notion database IDs and Discord role/channel IDs differ between a dev bot and production.
</Callout>

## RoleSyncerOptions

Drives the sync between Notion member/team databases and Discord roles.

| Field | Type | Description |
| --- | --- | --- |
| `TeamsDatabaseId` | `string` | Notion database ID for teams. |
| `TeamNamePropertyName` | `string` | Property name for a team's name. |
| `MembersDatabaseId` | `string` | Notion database ID for members. |
| `DiscordUsernamePropertyName` | `string` | Property name for a member's Discord username. |
| `ActivePropertyName` | `string` | Property name for a member's active status. |
| `ClubPositionsPropertyName` | `string` | Property name for a member's club position(s). |
| `DisciplinesPropertyName` | `string` | Property name for a member's discipline(s). |
| `TeamsPropertyName` | `string` | Property name for a member's team(s). |
| `TechnicalLeadRoleId` | `ulong` | Discord role ID granted to technical leads. |
| `TechnicalLeadRegex` | `string` | Regex matched against a member's club position(s) to decide who gets the technical lead role. |
| `InactiveRoleId` | `ulong` | Discord role ID applied to inactive members. |
| `SafeRoleIds` | `ulong[]` | Role IDs whose holders are skipped entirely by the syncer. |
| `IgnoredRoleIds` | `ulong[]` | Role IDs the syncer never removes, even if otherwise out of sync. |
| `InactiveMessage` | `string` | DM sent to a member when they're marked inactive. |

<Callout type="idea" title="Changing TechnicalLeadRegex">
    This regex is matched against the raw "Club Position(s)" text from Notion, so test it against
    real values before changing it — a bad pattern silently grants or withholds the lead role
    rather than erroring.
</Callout>

| `MembersDatabaseId` | `string` | Notion database ID for members. |

## RepeatingCalendarEventsOptions

| Field | Type | Description |
| --- | --- | --- |
| `RepeatEveryPropertyName` | `string` | Property name for a meeting's repeat interval. |
| `RepeatUntilPropertyName` | `string` | Property name for a meeting's repeat end date. |
| `OriginalEventPropertyName` | `string` | Property name linking a repeated instance back to its original event. |
| `EventTimePropertyName` | `string` | Property name for a meeting's event time. |
| `TimeZone` | `string` | IANA timezone used when generating repeated event instances. |

## WebhookListenerOptions

| Field | Type | Description |
| --- | --- | --- |
| `Prefixes` | `string[]` | HTTP listener prefixes. Defaults to `["http://*:8080/"]` — only needs a `config.json` entry if you're changing the port. |
