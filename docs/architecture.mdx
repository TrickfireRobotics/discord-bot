The bot is a .NET generic host (`Microsoft.Extensions.Hosting`) running a collection of
independent services, most of which either react to Discord/Notion events or poll on a timer.

## Service layout

| Folder | Contents |
| --- | --- |
| `Services/` | Cross-cutting services: `BotState`, `RoleSyncer`, `AttendanceTracker`, `WebhookListener`. |
| `Services/Discord/` | Discord-specific services: the client wrapper, slash commands, message logging, join/feedback/club-info flows. |
| `Services/Notion/` | Notion-specific services: the Notion client setup, webhook handling, repeating calendar events. |

## Auto-registration

Rather than hand-wiring every service into the DI container, `Program.cs` reflects over the
assembly at startup and auto-registers anything implementing `IAutoRegisteredService`:

```csharp title="Program.cs"
foreach (Type type in asm.GetTypes())
{
    if (!typeof(IAutoRegisteredService).IsAssignableFrom(type) || type == typeof(IAutoRegisteredService))
    {
        continue;
    }

    MethodInfo registerMethod = type.GetMethod(nameof(IAutoRegisteredService.Register), [typeof(IHostApplicationBuilder)])!;
    registerMethod.Invoke(null, [builder]);
}
```

Each service implements a static `Register(IHostApplicationBuilder)` method that wires up its own
DI registrations and config binding (via `ConfigureTypeSection<T>`, see
[Configuration](./configuration.mdx)). Adding a new service is just: implement
`IAutoRegisteredService`, write `Register`, and it picks itself up — no central registration list
to maintain.

<Callout type="idea" title="Adding a new service">
    Look at an existing small service like `JoinMessageEvent` as a template: implement the event
    handler interface you need plus `IAutoRegisteredService`, and register your options/DI
    dependencies in the static `Register` method.
</Callout>

## The Discord client and `MainGuild`

`DiscordService` wraps the DSharpPlus `DiscordClient` and exposes `MainGuild`, the live handle
most other services use to reach Discord data (channels, roles, members):

```csharp title="Services/Discord/DiscordService.cs"
public DiscordGuild MainGuild => Client.Guilds[Options.MainGuildId];
```

This is a computed property, not a cached field — it always resolves to whatever guild object
DSharpPlus's own cache currently holds. That matters across reconnects: DSharpPlus rebuilds its
guild cache from scratch on every reconnect, and `MainGuild` needs to track that rather than
pinning a stale snapshot from whenever the bot first connected.

<Callout type="warning" title="Don't cache MainGuild yourself">
    An earlier version of this code captured `MainGuild` once at startup and used reflection to
    force DSharpPlus's cache to keep pointing back at that same object after every reconnect.
    That fought the library's own cache lifecycle and caused a slow memory leak that only showed
    up after days of uptime with periodic reconnects — not in short local test runs. If you need
    guild data, go through `MainGuild` (or `Client.Guilds` directly) each time rather than storing
    a reference.
</Callout>
